# L5 E lane — paragraph jobs for the 60 eligible type-E papers

Hand-coded, one paper at a time, same discipline as `lanes/L4-b-ledger` and
`lanes/L1-f-structure`. No batch classifier: `para_extract.py` measures line
geometry, `dump_paper.py` writes the reading list, `record.py` validates and
assembles, `check.py` recounts. Every job in `jobs-e.jsonl` is read off the page or
off the paper's own text layer.

## Method

1. **Queue.** `queue.txt` is manifest order; one paper is finished (layout, record,
   recount, note) before the next is opened.
2. **Measurement.** `python -I lanes/L5-e-ledger/tools/para_extract.py layout <pid>`
   rebuilds paragraph boundaries from PyMuPDF geometry. The measured block numbers
   are the only legal unit of a `groups` entry.
3. **Reading.** `python -I lanes/L5-e-ledger/tools/dump_paper.py <pid>` writes
   `.proxy/<pid>-read.txt` with every block (number, kind, pages, words, first 380
   and last 80 characters). The text layer is authoritative for wording; the
   rendered page is consulted when a boundary is doubtful.
4. **Coding.** One job per printed paragraph. A *group* is the list of measured
   blocks that form one printed unit: a bullet list split line by line by the
   layout, a display equation torn from its introducing sentence, a sub-heading
   glued to the body that follows, a paragraph split by a page break. Groups follow
   the printed page, not the measured count.
5. **Chapter labels.** Stored `chapter_layouts` names are kept verbatim; no renaming
   in this lane. Where a stored bucket has no printed section, the paper gets
   `records/<pid>.skipped.json` naming either an exclusion class or the record that
   already holds the text. Nothing is dropped silently. The reverse case — a printed
   section the corpus files under no bucket — is coded inside the bucket whose topic
   it extends, with the delta note saying so: the acronym table of
   `P-E-2018-88902-cefa4db9` under `assumptions`, and Appendix A Data of
   `P-E-2018-93840-dffa6997` under `data-preprocessing`, since the appendix describes
   the same indicators as the metrics section.
6. **Page numbering.** `pages` in a record are file pages, as measured by the layout.
7. **Evidence.** Every group carries a verbatim opening and closing sentence
   (`units[].open` / `units[].close`) produced by `record.py` from the measured text.
8. **Delta discipline.** `group_count` equals the stored `paragraph_count` unless the
   record's note contains `Delta` or `Stored count` and says why. E buckets routinely
   span several printed sections (the E corpus files 2.3-2.5 and 4-4.4 under one
   `model-establishment` bucket), so both directions occur.

## Scope decisions for E labels outside the fourteen-value vocabulary

E stores 23 distinct chapter labels across the 60 queued papers (3,311 paragraph
slots). Four are not chapter functions and one is a printed variant:

- **`title` (0 stores in E)** — out of scope, same class as `abstract`, `references`,
  `appendix`; recorded as `front-matter` if a paper ever carries one.
- **`limitations` (21 stores)** — kept verbatim and coded as its own chapter, not
  merged into `strengths-limitations`, so stored counts stay comparable.
- **`strengths` (21 stores)** — same: kept verbatim and coded.
- **`error-analysis` (1 store)** — kept verbatim and coded.
- **`sensitivity-robustness` (25 stores)** — the E corpus's own name for
  sensitivity analysis; kept verbatim, not remapped to `sensitivity-analysis`.
- **`future-improvements` (2 stores)** — kept verbatim and coded, first met in
  `P-E-2018-89499-90bc677f` (section 9 Future work), so it stays comparable with
  stored counts rather than being folded into `conclusion` or `limitations`.

Any later merge of these families belongs to the merge audit, not to this lane.

## Coverage discipline

A contents page is detected by its dotted leaders. Where a paper sets a lone
`Contents` heading above the dotted lines, the heading carries no leaders of its
own and the page would otherwise show one contents block, leaving the heading
`unexplained`; `CONTENTS_LABEL` counts the heading as a contents block for the
page test (`P-E-2016-53494-99855cf8`, page 2). A dotted contents line that opens
with `Appendix` also used to arm the appendix scan early and swallow every later
miss; contents lines are now skipped when that start is located
(`P-E-2017-65123-e36461ec`, block 21). A third variant appears where the paper sets
its contents leaders with middle dots (`·`) instead of periods
(`P-E-2018-88902-cefa4db9`, page 3, fourteen lines that would otherwise be
`unexplained`); `TOC` accepts `·{4,}` alongside its existing `…{3,}`. These three are
the lane's only changes to the borrowed checker.

`reports/coverage.json` is written by `check.py --coverage` and recomputes, per coded
paper: `dup` (a block in two groups), `extra` (a coded block the layout does not
contain), `miss` (an uncoded block inside the coded page range, classified as
`front-matter` / `contents` / `banner` / `reference` / `appendix` / `unexplained`),
and the assertion `len(units) == sum(group_count)`. `unexplained` must stay empty and
no paper may appear with `dup`, `extra` or unequal counts.

## Tools

| tool | what it does |
|---|---|
| `tools/build_queue.py` | rebuilds `queue.txt` from the manifest (60 of 69 E rows) |
| `tools/para_extract.py layout <pid>` | measures paragraph boundaries into `layout/<pid>.json` |
| `tools/dump_paper.py <pid> [head] [tail] [lo] [hi]` | writes `.proxy/<pid>-read.txt` |
| `tools/record.py <pid>` | validates a paper's records, writes `jobs-e.jsonl` + `notes/<pid>.md` |
| `tools/check.py <pid>` | per-paper stored-count / evidence check + layout reproducibility |
| `tools/check.py --coverage` | writes `reports/coverage.json` (dup / extra / miss by class) |

The tools are the B lane's, retargeted to `L5-e-ledger` / `jobs-e.jsonl` / type `E`;
no behaviour was changed except the lone-`Contents`-heading rule in
`classify_miss` described under Coverage discipline.
