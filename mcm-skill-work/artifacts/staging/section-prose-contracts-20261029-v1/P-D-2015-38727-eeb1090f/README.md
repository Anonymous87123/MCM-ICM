# 章节职责与文字交接：九个上层、十九个下级合同

本补充对应计划§8.7的实际缺口：旧v5已有九个上层五段合同，但没有明确问题、过渡证据和正面组织模式，下级标题也未逐项展开。[section-contracts.draft.json](section-contracts.draft.json) 现在增加这些内容，并给十九个下级小节分别记录input、rhetorical job、analytical job、output和handoff。九个上层原合同按精确ID引用，不改动冻结字节。

| 上层部分 | 正面的文章职责 | 交接性质 |
|---|---|---|
| Summary | 先交代用途、条件、构造、范围，再预告案例与展望 | 方法细节有明确指向；转入Introduction主要依赖章节顺序 |
| Introduction | 从约束建立任务，经操作定义与权衡收束到用途 | Thus在节内闭合用途论证，不能误说它直接宣布下一标题 |
| Methodology | 解释用途与共同约定，再定义并列维度 | Results明确回指此前procedure |
| Results | 说明多样案例的比较目的 | 案例开头用目的句转向目标设定的演示 |
| Case study | 先界定案例和参照角色，再解释各分项需求 | 方案开头明确说回应部分已识别问题 |
| Development plan | 把诊断交给有部件、条件、分配标准和伙伴的方案 | 下一部分把实施方案交给假设更新，不是估计响应函数 |
| Scenario inputs | 声明变化范围、固定余项和时间范围 | 结果正文明确回指更新 |
| Projected outlook | 保留总体方向与不改善分项 | 后续标题转入可靠性和解释范围，不能写成验证了预测 |
| Strengths/limits | 将输入、表征和主体控制边界转成未来工作 | 作者正文终止后是文献来源，不凭空增加结论节 |

十九个下级合同覆盖两处引言小标题、六个指标定义、案例参照框架、六个案例分项和四个方案小节。定义、分项解释、方案列表各自是并列展开；阅读顺序不意味着前一模型的数值输出传给后一模型。每个正面组织模式都写成不依赖具体国家、数值或模型名称的动作，但这不是新增十九个跨论文规则。

## 核验与保留边界

[verification.json](verification.json) 记录四个直接输入、v11/v13传递输入、28个过渡提示的核对结果。标题和见证基于文字层，不能认证视觉边界；词句定位使用已有引号、破折号和空白归一化，原字节另由哈希保护。2,619个冻结语料输入未变，历史链及最新事件绑定错误均为0。

按PDF技能要求，文字提取不足以验收版面。当前只补可观察的正文组织，没有阅读公式、参数表或图形；指标定义合同只描述其文字职责，不声称保真保留了方程。官方题面与完整任务链尚需单独证据，G2/G4、完整版面和整篇关闭仍未通过。v13的41单元、40机制、68见证、82例句和单篇支持不变；没有安装规则、修改历史或删除旧成果。
