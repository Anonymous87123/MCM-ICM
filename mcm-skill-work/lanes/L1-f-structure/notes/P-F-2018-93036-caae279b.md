The memo is bound first, before the contents, and it is the only place where the paper states its policy claims in plain prose. It opens with a data-growth argument (IDC: 40-fold by 2020), defines PI as 'everything a person makes and does', then enumerates the seven domains the model later uses (digital identity, relationships, communication logs, media, financial, health, institutional), the subgroup concept, and the risk list - all of which are copied verbatim into the introduction at blocks 72-81, so the memo and the introduction overlap almost completely. The four recommendations are government purchasing power, trust mechanisms, privacy-by-design in new services, and an international dialog including Asia-Pacific and emerging economies. The memo's one analytic claim, that private data should not be trackable by government 'for national security concerns', sits oddly against the later chapter that treats NSA-type agencies as a legitimate buyer class. Block 60 carries both the memo's last line and the whole table of contents, which is why the TOC has no separate start block.

## introduction — 1 Introduction (1.1 Background, 1.2 Our Work) (pp. 7-8, 7 blocks)

`ext:context → ext:context → ext:context → ext:context → route → route → route`

Four blocks of sourced background (16.1 zettabytes per day in 2016 rising to 163 by 2025; analytics in insurance and marketing; breaches and social-network exposure; subgroup heterogeneity) and three blocks of method. There is no problem statement beyond 'quantify the cost of privacy', which was already given in the memo; the introduction's actual work is to name the three techniques - vector representation with a value predictor, a dynamic market system, and the social-network model - and to promise that each is tested 'under diverse conditions'. The claim that the results are 'interesting and reasonable' is the closest the paper comes to a hypothesis. ## assumptions — 2 Assumptions and Nomenclature (pp. 8-9, 7 blocks)

`route → route → limit → limit → limit → limit → define`

Three assumptions and a justification paragraph, then the nomenclature table. The assumptions are strong and each removes a hard part of the problem: PI splits into a fixed number m of categories (which is what makes the vector representation possible); fraud and harassment profits are excluded (so all data value is socially productive); and a trusted third party manages and sells the data under owner permission (so the market has no leakage and no resale). Assumption 3 is the one the breach chapter later contradicts, because a massive breach is exactly the failure of the trusted third party, and the paper handles that by saying the price falls rather than by relaxing the assumption. The nomenclature table (blocks 91-102) is 12 rows of symbols and is the only definition of v, C, T, t, N, omega, tau, mu.

## model-establishment — 3.1 Vector-based representation: feature vectors, correlation matrix, amendment (pp. 9-13, 31 blocks)

`route → route → define → define → define → define → read-figure → read-figure → route → route → define → derive → define → source → define → define → define → define → define → define → route → route → define → derive → define → derive → compute → interpret → derive → derive → define`

The representation chapter is the paper's best construction. An individual becomes a 5-vector over demographics, family and health, property, activities and consumer data; the vector is built by an attribute-value lookup table (Algorithm 1 sums the value vectors of every matched condition), and the table's entries come from the Financial Times' price list - a general person is worth $0.0005, while 'being engaged' or 'having a heart disease' each add a specific dollar amount in one dimension. That design choice (one nonzero entry per condition) is deliberate, to keep categories uncorrelated for the later correlation matrix, which the text says explicitly. A query is a second 5-vector of requested intensity, and the raw value is v = sigma(P) C Y^T with C a correlation matrix estimated from the same feature vectors; C's off-diagonals are computed (0.82 between demographics and property, 0.16-0.69 elsewhere) and the matrix is printed in full, which is rare in this corpus and makes the step checkable. The amendment then multiplies the raw value by exp(omega T - tau t) times N^mu, with omega = 1.28e-3, tau = 9.50e-4 and mu = 1.05 taken from Information Rules - so freshness decays the value and sequence length and record count raise it, and the parameters are borrowed rather than fitted. Two problems: the correlation matrix is symmetric but the text lists only six of ten off-diagonal pairs, and the value vectors in Table 2 are single entries with no source beyond 'our database'.

## model-establishment — 3.2 Dynamic market system and pricing strategy (pp. 13-16, 16 blocks)

`route → derive → define → derive → define → derive → define → derive → derive → derive → interpret → route → source → define → define → derive`

The demand chapter is imported wholesale from an empirical industrial-organisation paper and only partly re-purposed. It starts with a benefit-risk share lambda = s_benefit/(s_benefit + s_risk), whose risk scores are a 4x5 table of hand-set numbers by risk type and level (financial 0.05-0.128, health 0.06-0.24, family 0.05-0.22, social 0.03-0.17), then writes demand as D(j) = lambda_j P_j - r_j times a weighted sum over related individuals. Blocks 149-161 then present a finite-mixture agency-type model with a Bellman continuation value and a type distribution mu_theta - a serious demand system, but none of its parameters is estimated anywhere in the paper and the notation (theta, j, k, v, V, E_theta) is never connected back to the price equation. 3.2.2 supplies the empirical anchor instead: $42.8bn US internet ad revenue in 2013, $4 per user for Facebook and $24 for Google from a JPMorgan study, Mozilla and CDC as non-commercial buyers, and then P_agency = sum tau_j Q_i over three agency classes (commercial, NPO, government) whose purchasing powers Q1 > Q2 > Q3 are asserted, not measured. The chapter's structure is honest about the gap - it labels the mixture model 'model exposition' - but the two halves do not produce a single combined result.

## model-establishment — 3.3 mCAF: multi-dimensional clustering for social networks (pp. 15-18, 19 blocks)

`route → source → define → source → derive → derive → define → define → define → derive → derive → derive → derive → define → derive → route → read-figure → read-figure → derive`

The clustering algorithm is the paper's only original method and it is defined completely: four measurements (social circles from mutual friends plus interaction value, regions as a weighted sum of four hometown/residence distances, organizations as a 0/1 same-school-or-employer flag, and tie strength from the cited TreeIt method), each normalized, then combined into a structure similarity as a weighted inner product of per-measurement node summaries. A threshold s_k filters neighbours, the algorithm is stated as Algorithm 2, and it is run on 600 Facebook users through the Graph API, giving eight clusters (Fig.3). The distance weights alpha, beta, gamma, delta in R_ij and the thresholds s_k are all introduced as parameters 'estimated via training' and no values are reported, so the clustering cannot be reproduced from the text. The chapter closes with the network-effect function I = log(1 + sum d_i), i.e. information grows logarithmically in data volume, which is the claim the summary sheet calls 'the relationship between data and value is not linear, but log-likelihood' - the term is used loosely, since no likelihood is computed.

## results — 4 Experimental results (Tasks 1-7) (pp. 18-25, 46 blocks)

`route → route → route → source → read-figure → read-figure → read-figure → read-figure → read-figure → compute → route → compute → read-figure → compute → read-figure → interpret → ext:context → interpret → select → select → route → route → define → define → define → route → source → source → source → source → read-figure → select → interpret → interpret → read-figure → read-figure → define → route → route → select → select → source → interpret → read-figure → interpret → select`

The results chapter stretches Task 1 to Task 7 across seven subsections and its quality varies by an order of magnitude. Task 1 is real work: PIDATA is 600 Facebook users, the six subgroup feature vectors are shown (Fig.6), the value components per subgroup are shown (Fig.7), and the protection price point is derived from an IBM breach study - $141 per stolen record against a few dollars of trade value, a 70-fold ratio, with a 27.7% two-year breach probability - so protection is priced as insurance. Task 2 is a survey of 77 adults producing query vectors for five domains (Table 5), and the observed pattern (health queries weight the health dimension at 0.99, social media weights the family dimension at 0.96) is plausible but the sample is small and unweighted. Task 3's supply-demand conclusion is a verbal corollary of P_agency with no simulation. Task 4 is the longest subsection and is almost entirely legal exposition - Privacy Act, GDPR (72-hour breach notification), PIPEDA, APPI's uchi/soto and honne/tatemae analysis - plus a world map of data value by country; its conclusion, that privacy should be a basic human right, contradicts the memo's position that PI is an asset to be traded, and the paper never reconciles the two. Task 5's generational argument is three paragraphs with no data, and its PI/PP/IP comparison is grammatically broken ('PI and PP are both private while PI and PP are both abstract'). Task 6 reports the mCAF conclusions (network effects exist; the community is responsible) and Task 7 reuses the lambda-and-r machinery to show the price falls after a breach, then recommends direct compensation.

## sensitivity-analysis — 5 Sensitivity analysis (Demand model, mCAF) (pp. 25-26, 7 blocks)

`route → interpret → derive → route → derive → check → compute`

Two sensitivity exercises, neither of which perturbs the price model. The demand one is a difference-in-differences regression of log retention on provider and time fixed effects plus provider-specific trends, which estimates heterogeneous price sensitivity - a defensible design, but its coefficients are not reported, so the section demonstrates a method rather than a result. The mCAF one is the paper's actual robustness claim: the algorithm is randomized in its initial centres, run eight times, and a metric delta compares the runs; Table 6 gives eight values between 0.013 and 0.051, and the conclusion is that delta is small so the clustering is stable. That is a legitimate stability test of a randomized algorithm and it is the only place in the paper where the same computation is repeated under controlled variation. What is missing is any sensitivity of the price to omega, tau, mu, the correlation matrix or the risk-score table - the parameters the whole model rests on.

## conclusion — 6 Conclusions and future work (pp. 26-26, 3 blocks)

`ext:claim → limit → handoff`

One block restating the three components, one admitting that the correlation matrix and other parameters need a large dataset to be estimated precisely, and one proposing neural-network value predictors and a larger dataset as future work. The limitation is the honest one and it is the same gap the body shows: nearly every coefficient in the model (AHP-free, risk scores, agency purchasing powers, distance weights, thresholds) is hand-set, while the one estimated object - the correlation matrix - is estimated from 600 users. The proposed AHP fix is odd, since AHP would add more judgement rather than less data. The reference list begins after block 288.
