## model-establishment — Task 4: Policy to Support Refugee Model (pp. 15-17, 11 blocks)

`route → select → define → define → define → derive → define → define → derive → compute → interpret+close:select`

The policy chapter is written as a second model, not as advice. ## results — Task 5: Exogenous Events (pp. 17-19, 10 blocks)

`mechanism → mechanism → define → define → derive → define → derive → derive → read-figure → interpret`

## results — Task 6: Scalability (pp. 19-21, 10 blocks)

`define → define → define → mechanism → define → derive → define → mechanism → read-figure → interpret+close:limit`

The scale-up chapter adds three new quantities (traffic Tr, basic livelihood Ls, conflict factor Cf) and one inequality (32) that calls the difference between transport capacity and need a 'probability of conflict'. All three are definitions with no data, and the only mechanism block is the verbal chain 'greater conflict factor -> greater probability of conflict -> harder to receive'. The result is one degree-distribution figure (11) and one sentence that fixes the model's validity window: valid below ten times the scale, degraded at fifteen. That sentence is the paper's only quantified scalability claim.

## sensitivity-analysis — Stability and Sensitivity (pp. 21-21, 4 blocks)

`ext:claim → check → check → compute+close:interpret`

Four blocks. The first is a pure claim ('our model is practical and reliable') with no evidence. The second turns the Task-4 data change into a stability argument ('we add some data or remove some out ... will not have large fluctuations'). The third and fourth are the only actual test: the ignored preparation time is added as a criterion and the weights are recomputed; the verdict is qualitative ('changes a little', 'rather small'), with no coefficient reported. Measurement puts these blocks out of reading order on the page (the sentence beginning 'Taking it as a new criterion' follows its own fragment), which is why 199-201 read as three pieces of one test.
