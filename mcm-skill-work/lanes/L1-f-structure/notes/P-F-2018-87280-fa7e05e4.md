# P-F-2018-87280-fa7e05e4 — chapter jobs (hand-coded)

## introduction — I Introduction (Task restatement) (pp. 2-2, 9 blocks)

`route → route → route → route → route → route → route → route → route`

The introduction is not an argument, it is a task list: eight numbered restatements of the ICM problem, one short block each, with a single framing sentence at the top ('the commercialization of privacy becomes an important issue ... we need to establish a privacy pricing system'). The summary sheet had already restated the same eight tasks as the team's own answers (Task1 ... Task8), so the same list appears twice with different tense. Three tells of the translation: the tasks are phrased as 'consider ...', 'make sure ...', 'judge ...', no task states a success criterion, and block 20 asks about 'the similarities and differences between PI and PP and IP' which the problem does not ask. Block 14 carries the summary-sheet tail and the 'I Introduction' heading, hence the grouped first record.

## model-establishment — II Categorize individuals into sub-groups (Task 1): 2.1-2.1.1 (pp. 2-4, 12 blocks)

`route → source → interpret → route → define → read-figure → route → define → define → define → define → define`

Task 1 is solved by assertion plus a five-bucket taxonomy. The literature block is the only sourced block in the paper's first half (Culnan on privacy concern, Hagel on compensation, Adjei on monetisation) and the conclusion drawn from it - people will sell if the price is right - is the paper's foundational premise, never tested. The taxonomy is 26 indicators in five classes (citizenship, social contact, finance, health/medical, personal assets); the class justification is one bullet each, written as sentence fragments and measured as two or three blocks per bullet (blocks 31-40). No indicator is defined, no source is given for the 26, and the classification never feeds a later computation directly - the coefficients in section 3 are computed per indicator, so the five classes are presentational only. Figure 2-1 is cited but not read; it carries the only visual of the taxonomy.

## model-establishment — III Privacy cost model (Task 2): 3.1-3.2 model building (pp. 4-9, 42 blocks)

`route → route → define → define → select → select → define → define → derive → define → route → source → read-figure → define → source → derive → derive → derive → check → derive → derive → derive → check → compute → define → source → define → derive → compute → route → derive → define → route → select → derive → define → define → define → derive → read-figure → compute → define`

The pricing model is a three-part sum - expected income value, risk value, information-related value - and the chapter is really a methods tutorial for each part. Expected income: citizenship's ten indicators are weighted by AHP, with the full textbook sequence reproduced (reciprocal matrix, column normalisation, eigenvector, maximum eigenvalue, CI, RI from 500 random matrices, CR < 0.1, weights summing to 1), and the weights are then quoted to three decimals but only to two for the last entry (0.20), which is the only arithmetic slip visible. The other 16 indicators are valued by the present-value method of intangible-asset accounting, then their coefficients are produced by a Gradient Boosting Decision Tree in Python whose hyperparameters are tuned 'by adjusting the steps, iterations, maximum depth ...' with no validation split described. Risk: coefficient of variation per indicator, times an AHP weight used again as a risk coefficient, summed - the same weights serve two different roles, which the text does not address. Information-related value: a Gaussian mixture whose density a·exp(-(delta-mu)^2/2sigma^2) is fitted by maximum likelihood in MATLAB, with delta a 'correlation degree' that is never defined operationally. The chapter's real weakness is visible in its own structure: three different valuation logics combined by addition, with no argument for why the three are additive or commensurable.

## results — 3.3 Model solution (data, coefficients, price) (pp. 10-12, 9 blocks)

`define → source → define → compute → compute → define → compute → compute → interpret`

The only calibration chapter, and it is thin. Data are 1997-2016 Chinese census and consumption series from the National Bureau of Statistics, cleaned by fuzzy matching and standardised by Z-score, with the standardisation choice justified by a citation rather than by an effect on the result. Coefficients come out in Tables 3-2 and 3-3 (not reproduced in text), and the pricing is then run on 500 simulated individuals with a 0/1 indicator for whether each of the 26 items is provided. The two headline numbers are $600-3000 per person and $5578 per year when all 26 items are supplied - a 9x spread that the paper presents as a range without explaining which items drive the low and high ends. No validation against an actual transaction, no comparison with an existing data broker price, and the coefficient table is the only place the GBDT output is visible at all.

## model-establishment — IV Pricing system and demand elasticity (Task 3) (pp. 12-13, 11 blocks)

`route → route → define → derive → define → source → route → derive → define → read-figure → interpret`

Two small models in one chapter and neither is estimated. The price is B = CP + S, i.e. privacy cost plus a seller's margin, and the margin is capped at 30% by an appeal to 'the profit margin of a commodity is roughly 10%-30%' with no source - the number is the whole content of the pricing rule. Demand elasticity is imported verbatim from microeconomics, Ed = (dQ/dB)(B/Q), with the sign flipped for convenience, and the five textbook elasticity cases are tabulated but never computed for privacy. The life-cycle figure divides the market into development, mature and decline periods and the interpretive block argues that demand is more elastic early and rigid later; that is the chapter's one substantive claim, and it is stated, not derived. Note the section heading numbering skips 4.3 and the chapter ends by gluing the next section's heading into block 110.

## assumptions — 5.1 Assumptions and constraints of personal information pricing model (pp. 13-14, 4 blocks)

`route → limit → limit → limit`

Three assumptions, unusually short for this corpus and unusually honest. The first is a homogeneity assumption with a distributional excuse (attention to privacy is roughly normal, so it depends only on individual characteristics and information field) - which is the assumption the whole coefficient scheme rests on, since coefficients are person-specific only through the indicators. The second excludes political and military data as unquantifiable by general standards. The third confines the model to the 26 chosen factors. What is missing is stated nowhere: the model assumes individuals own and may sell their data, and that the market clears, both of which the memo then treats as policy variables. The 5.2 human-rights heading is glued to the tail of block 115.

## results — 5.2-5.3 Privacy as human rights and dynamic analysis (Task 4) (pp. 14-15, 10 blocks)

`select → define → select → route → interpret → route → define → compute → compute → interpret`

The human-rights discussion reaches a clear and defensible position in three blocks: privacy should not be fully protected as a human right because personal information carries both personality and property interests, so the answer is desensitisation rather than prohibition. That is a stronger argument than the corresponding chapter in most papers in this corpus, and it is made without the model - it is a legal-philosophical position with one citation. The dynamic analysis then adds time in the cheapest possible way: each of the 26 risk coefficients becomes a function of t, illustrated by fitting total assets with an exponential (r18 = -0.6404 exp(-0.07066t + 0.6887), R-squared 0.9779) and asserting 'by fitting the other 25 indexes in the same way'. The exponential form is chosen by the fitting toolbox, not by a theory of how risk grows, and the negative coefficient means the risk factor falls with time - the opposite of the chapter's own verbal claim that risk increases as privacy awareness spreads.

## model-establishment — VI Generational differences and PI/PP/IP comparison (Task 5) (pp. 15-16, 15 blocks)

`route → route → source → source → source → source → compute → define → limit → read-figure → route → define → define → define → read-figure`

Two unrelated halves. The generational half regresses consumption by age across five domains from three Chinese data sources and reads a curve that rises from 19 to 63; the model change is to scale each dimension's value by the growth factor, with the average growth value offered as a shortcut when precision is not needed - a limit rather than a method. Nothing is estimated for the price effect of age: no coefficient, no elasticity, no comparison of a young and old seller. The PI/PP/IP half is three definition blocks (PI non-public with immeasurable long-term risk; PP as tangible/intangible property whose value is independent of the owner; IP as rights from creative activity with no disclosure risk) and one figure showing the conceptual overlap. It answers a question the problem did not ask, and it never re-enters the model.

## model-establishment — VII Network effects of data sharing (Task 6) (pp. 16-18, 18 blocks)

`route → interpret → route → limit → limit → limit → limit → limit → limit → route → define → read-figure → compute → interpret → route → define → interpret → interpret`

The network chapter is two models that do not talk to each other. The small-world simulation has six assumptions (economic man; a seller leaks two neighbours' data plus a probability p of non-neighbours; sales are public; equal influence; equal leakage to self and neighbours; no human-rights constraint) and a 40-person population swept over n and p, and its result is the expected monotonicity - more sellers and more rewiring means more leakage. The game-theory half then argues the same point verbally as a prisoner's dilemma and concludes that a sub-game perfect equilibrium without regulation is welfare-dominated, which is the paper's clearest policy result: individual rationality destroys the group's privacy, so restriction is necessary. The two halves are never linked - the simulation does not produce payoffs and the game does not use the network - and the 'dynamic game' promised in the heading is a static 2x2 described in one table. The 40-node scale is the smallest in the corpus for a network claim.

## results — VIII Impact of data disclosure on privacy value (Task 7) (pp. 18-20, 17 blocks)

`route → route → define → define → define → interpret → read-figure → route → source → read-figure → define → define → read-figure → interpret → source → read-figure → derive`

The breach chapter is entirely qualitative, and it is the paper's most coherent narrative: a leak lowers b (firms' willingness to pay) and raises perceived risk, so both the expected return and the related value fall, which the paper draws as a declining value path (Figure 8-1). The time-effect section then borrows the long-tail and bullwhip effects to argue the impact rises, falls and oscillates - two named effects, no parameters, one figure. The compensation model is the only equation: U = I + Pi, where Pi is an actuarial 'other losses' term that is never computed, so the compensation formula is a definition rather than a model. The chapter does answer the question the problem asked (who should bear responsibility) only implicitly, through the memo's recommendation of agency compensation.

## sensitivity-analysis — IX Sensitivity analysis (pp. 20-21, 5 blocks)

`route → read-figure → compute → read-figure → check`

The sensitivity test is a questionnaire: respondents re-weight the value and risk coefficients, the model is re-run, and the new prices are compared with the original by an independent-samples t-test in SPSS. Homogeneity of variance gives p = 0.775 and the t-test gives p = 0.910, and the paper reports 'no significant difference, so the stability of the model is good' - but the quoted p = 0.910 is then described as '< 0.05' and 'we can't accept the original hypothesis', which contradicts the conclusion in the same sentence. The test is also circular in a second way: the questionnaire asks people to redo the AHP pairwise comparisons, so it tests whether respondents agree with the authors' weighting, not whether the price is right. No coefficient is perturbed by a fixed percentage and no price range is reported, so this is a robustness claim about preferences, not about the model.

## strengths-limitations — X Analysis of the advantages and weaknesses of the model (pp. 21-22, 2 blocks)

`ext:claim → limit`

Four advantages in one block (many parameters, emergency pricing included, simple and adjustable, novel method with high R-squared) and three weaknesses in the next (parameters need case-by-case adjustment, not everyone accepts privacy commercialisation, coverage is not exhaustive). The advantages are all method labels with no result attached; the third is the one the sensitivity chapter actually supports, since re-weighting barely moves the price. The weaknesses omit the two the body itself exposes - the additive combination of three incommensurable values, and the negative time coefficient in the dynamic model. The memo's title and salutation are glued to the tail of block 187, so the memo has no heading block.

## memo — Privacy Pricing Policy Recommendations (letter to the decision maker) (pp. 22-24, 22 blocks)

`route → route → route → define → define → define → route → define → define → define → select → interpret → interpret → select → select → select → select → route → select → select → select → select+close:handoff`

A letter to 'Dear decision maker' whose paragraphs are measured one line at a time - every block from 188 to 242 is a single typeset line, so the groups here are the real paragraphs and the literal count is roughly three times the group count. The structure is: why privacy pricing matters, what the team built, then the three price components (prospective earnings, risk assessment, relevance) and the extra factors (generational, age, unpredictable risk). The recommendations themselves are six, and they are the paper's best writing: macro-control with a price band, economic regulation, punishment for illegal use, restricted trading for special groups such as government personnel, agency compensation on top of information value, guided public opinion, market control, and fast response. Every recommendation is traceable to a chapter earlier in the paper except the price band, which no computation supports, and the claim that the model matches people's expected value within $10 comes from the sensitivity questionnaire rather than from the 500-person simulation.
